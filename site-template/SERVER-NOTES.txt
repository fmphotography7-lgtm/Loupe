Frozen Moments — serving notes
==============================

The site is plain files. Any web server will do. Two settings matter, and one of
them decides whether the printed QR labels work.


1. CASE-INSENSITIVE PATHS  (required before uppercase QR labels are printed)
---------------------------------------------------------------------------
QR codes encode uppercase about 40% more densely than mixed case, so an
uppercase link scans better at label size — but only if the server answers
/ART as well as /art. Domains are case-insensitive; paths are not.

The site.js in this folder already reads ?H= and ?ID= as well as ?h= and ?id=,
and compares artwork ids case-insensitively. The path is the remaining piece.

Caddy — the whole config:

    fmphotography.ca {
        root * /path/to/site
        file_server
        try_files {path} {path}.html {path}/index.html
        @upper path_regexp upper ^/([A-Z0-9_-]+)/?$
        redir @upper /{re.upper.1} 301
        # lowercase the captured segment with a map if you want a true rewrite;
        # simplest is to keep one lowercase file per page and redirect to it.
    }

nginx — the equivalent:

    location / {
        try_files $uri $uri.html $uri/ =404;
    }
    location ~* ^/art/?$ { try_files /art.html =404; }

The second nginx line is the one that matters: ~* makes it case-insensitive, so
/art, /Art and /ART all serve art.html. Add one line per page you link to from
a printed label. Nothing else needs it.

TEST BEFORE PRINTING: visit /ART?H=<a real venue code>&ID=<a real FMP id> and
confirm you land on that piece with the credited-to bar showing. Two scans of a
test label cost nothing; 200 wrong labels cannot be recalled.


2. TURN DIRECTORY LISTING OFF  (this one matters for client galleries)
----------------------------------------------------------------------
A client gallery is protected by two things: the manifest is encrypted, and the
photographs sit in a folder with a long random name that nobody can guess.

If the server has directory listing switched on, browsing to /client-images/
prints a list of every folder in it — and the random name stops being secret.
The encryption then guards a door standing beside an open wall.

robots.txt does NOT protect this. It is a request that well-behaved crawlers
honour; it is public, it names the folders, and it has no force at all against
anyone who simply types the address.

nginx — off by default, but be explicit:

    location /client-images/ { autoindex off; }
    location /client-galleries/ { autoindex off; }

Caddy — file_server has no listing unless you add browse. Do not add it.

Apache — listing is often ON by default. This is the dangerous case:

    <Directory "/path/to/site/client-images">
        Options -Indexes
    </Directory>

TEST IT: visit https://yoursite/client-images/ in a private window. You should
get 403 or 404, never a list of folders.


3. HTTPS
--------
Required by Square and Stripe, and by the browser for a service worker. Caddy
obtains and renews a certificate on its own. With nginx, use certbot.


4. WHAT NOT TO DO
-----------------
Do not open ports 80/443 on a home connection if it can be avoided — a
Cloudflare Tunnel gives the same result with no inbound path into the house,
and no static IP needed.
